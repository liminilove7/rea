# 自动打怪与任务功能：本次静态研究能够提供的基础

日期：2026-10-22。当前只有客户端资源；本文是后续功能设计，不表示已经实现自动战斗、实体识别或任务执行。

## 功能边界

本次得到的是神石、强化、PVP/PVE 属性及技能声明目录。静态物品/技能表能够说明“定义了什么”，不能说明“当前场景里有什么”。必须分开保存资源版本、运行时观察及效果结论，缺失字段保持未知。

| 模块     | 资源可提供的输入                                                           | 仍需的证据                                     | 建议界面                                   |
| -------- | -------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------ |
| 机制目录 | 神石物品→技能→效果，概率原值；强化规则；PVP/PVE声明                        | 当前可获取性、服务端启用情况                   | 搜索、原字段、关联技能、来源哈希、证据等级 |
| 技能约束 | activation_attribute、required_*、target_*、delay_id/time、cost_*、chain_* | 当前技能等级、冷却剩余、状态、实际资源消耗     | 候选技能和不可用原因；不把缺失当无限制     |
| 目标识别 | target_relation_restriction / target_species_restriction 等允许条件        | 当前实体ID、类型、存活、坐标、HP、归属和可达性 | 候选目标列表、刷新时间、身份有效性         |
| 行为规划 | PVE适用技能、连段前置和费用声明                                            | 角色职业、武器、技能学习结果、当前状态         | 规则优先级、计划动作、预计条件             |
| 结果观察 | 可识别的效果类别、伤害/控制标签                                            | 实际命中、抵抗、死亡、状态到期、位移和战斗记录 | 动作请求与观察结果分别显示                 |
| 任务流程 | 当前包未包含完整任务定义                                                   | 任务ID、接受/完成条件、NPC、地图与任务状态     | 任务步骤、完成证据、暂停原因               |

## 数据契约建议

- `MechanicCatalog`：sampleHash、sourceFile、recordId、rawFields、missingFields、skillJoin、claimKind。
- `SkillDefinition`：name/ID 与学习条件独立；原始时间、距离、概率与确认单位分开；普通主动技能与 Provoked 神石效果分开。
- `ObservedWorldState`：对象身份、采样时刻、玩家/怪物区分、生命状态、位置、目标关系、覆盖范围。过期或身份改变时不继续使用旧对象。
- `Decision`：选中目标、候选技能、前置条件、未满足原因、引用的资源版本与观察时间。
- `ActionResult`：请求已发出、动作表现、命中、实际伤害和任务状态更新分别记录，不能合并成一个 success。
- `ResearchEvent`：保留因果关联ID、来源和时间；神石成功/抵抗/免疫分开记录，不能把未观察到效果直接判为随机未触发。

这些名称是本次设计建议，不是声称已从 Game.dll 恢复出的原始类名或接口。

## 建议状态流程

`等待有效观察 → 选择目标 → 检查距离与目标关系 → 选择可用技能 → 等待结果 → 重新评估`

异常分支应覆盖：目标消失、角色死亡、对象重建、资源不足、位置不可达、战斗结果超时、人工暂停。当前没有已验证的移动、攻击、交互或任务执行接口，因此这里只设计边界和验收条件，不提供虚构调用地址。

## 本次可直接复用的规则

1. 神石按物品记录保留两个概率字段；left 缺失、显式0、与主列相等或不同都不能归一成“固定减半”。Provoked 效果不能作为普通主动技能直接加入释放队列。
2. 普通强化、option 六阶段表、跳跃强化、累计强化、技能赋予应为独立功能。客户端概率显示与服务端成功判定分别标记。
3. 自动打怪使用 PVE 场景；PVP 属性不直接计作打怪收益。技能中的 pvp_damage_ratio 也不能当通用伤害倍率。
4. 普通/a/b装备属性槽保持原分类，等待充能/激活消费者证据后再合并；不要只把所有数字相加。
5. 每次客户端更新重新核对样本哈希和资源关联。旧 Classic 样本的地址、规则与当前 TW 样本分开。

## 验收顺序

先完成可重复的资源目录查询和关系回查，再在用户可控制环境中验证只读实体及状态识别；之后才为明确的执行接口建立动作与结果记录。自动战斗的有效性需要目标与伤害事件证据，任务自动化需要任务状态变化证据。神石实际概率估计还需要定义试验单位、有效样本、抵抗/免疫分类与置信区间，不能用动画次数作为默认分母。

当前交付阶段：资源基础与客户端静态机制分析。没有实现或验证自动打怪/自动任务执行。
