# 第九轮 REA：反击技能字段、方向状态与收到的伤害数值

日期：2026-10-11。主流程：REA 6.1.0 MCP → IDA 8.3 离线数据库。目标 Game.dll SHA256 为 `834300c2a85b6427de2d4a4be2931ff2ea59fd70f48f31754f5c2181753bd786`。本轮复制原有数据库到单独目录再打开，没有运行、附加或修改游戏。

## 本轮结论

1. 当前客户端具名解析 `counter_skill`、`chain_time`、`chain_skill_prob1/2`。反击类型可映射为位掩码；这推进了“资源字段→客户端记录→分类登记→条件技能UI分支”的证据，但尚未找到实际技能可用性与服务器施放校验。
2. 找到方向相关分类、时间掩码更新及攻击结果相交的本地链。它不是已证实的盾牌反击窗口；不要将其中716/1382直接写成反击毫秒数。
3. `S_ATTACK` 的收到数值已追到战斗文字消费端。客户端这条显示路径读取收到的整数，再传入格式化函数，没有从装备攻防重新推导这项数字。这不揭示当前官方后台的伤害公式。
4. 仍未闭合当前版本 `pvp_damage_ratio` 的执行消费者；本轮没有把旧模拟器PVP模型升级成当前官方公式。

## 1. 资源字段与反击分类登记

REA 的 `53C3F0` 指令返回及反编译显示：`counter_skill` 分支 `53F7A7..53F7CB` 调用 `53C1B0`，将结果保存至 `[rbp+1D50h+var_15F8]`。本轮通过记录起点 `[rbp+1D50h+var_1D60]` 核对其相对位置：

| 当前技能记录字段 | 偏移 | 宽度/含义证据 |
|---|---:|---|
| counter_skill 解析结果 | +768 | qword写入，原始名称表返回32位数值 |
| chain_time | +7A0 | dword写入 |
| chain_skill_prob1 | +7A4 | dword写入 |
| chain_skill_prob2 | +7A8 | dword写入 |

这是客户端技能记录布局，不是玩家运行时基址。第九轮没有证明读取这几个字段的任何操作会改变服务器概率。

`53C1B0` 循环最多6项、每项步长16，匹配返回项内+8的低32位；未匹配返回0。作为辅助原始PE数据读取，`846B50` 表内容为：

| 原始小写表名 | 数值 | 十六进制 |
|---|---:|---|
| 1 / all | 480 | 1E0 |
| dodge | 128 | 80 |
| parry | 64 | 40 |
| block | 32 | 20 |
| resist | 256 | 100 |

资源中 `Block` 的大小写与此表不同；本轮未解析字符串比较入口 `6BC748` 或XML值的大小写规范化，因此表名映射与“这一条大写值在运行时成功装入32”保留为不同事实。该边界需要后续复核，不能直接跳过。

REA `39D860` 在取得技能记录后，读取+768；并在 `39E030..39E09B` 对3项登记掩码逐项执行 `(recordMask & tableMask)==tableMask`，随后调用 `39F2F0` 将该技能登记到相应容器。原始PE的 `937128/937140/937158` 三项掩码分别80/40/20。`39F2F0` 创建关系节点并加入技能条目，尚未证明它是实际施放资格检查。

REA `39D5D0` 对技能记录+768/+100/+108任一非零返回1；其调用者 `27FDE0` 构造 `UIChainNode`，通过 `541050` 查技能记录，在 `28028B` 调用该条件分类判断，然后在 `28029F` 进入 `aV4SkillSlotCon` 对应的UI模板分支。它证明条件技能有单独UI构建路径，不证明模板已激活、技能可施放或服务器会接受请求。下一步可沿实际控件类的更新/输入回调追踪。

所以：当前资源 `counter_skill=Block` 与客户端“盾防条件技能的分类登记”有代码对应；但“格挡几次→可以反击几次”的完整消费链仍未知。资源中的 `chain_skill_prob2=10` 在本轮只证明被读取为数字，不能作为格挡概率的10%乘数。

## 2. 对时间掩码的追踪纠正了一条容易误认的链

`480890` 是此前从收到攻击消息追到的动作消费者。本轮发现它读取组件+1A00/+1A04/+1A08/+1A0C，并与收到的逐项标记相交，分别写+1A10/+1A14或+1A18/+1A1C。如果只看这些相交和时间比较，很容易误命名为“反击窗口”。继续逆追写入者则发现：

```text
0213C0 的对象更新
  → 057930(对象, byte状态, int方向参数, 两项float向量)
      写 +19FC 的本地分类 0/1/2/4，部分状态保持旧值
  → 01B610：在分类变化时更新当前/历史状态与时间值
  → 068810：得到带时间条件的合并掩码
      → 1FBAB0 UI调用者
      → 368E50：写快照+3BC

收到 S_ATTACK → 430D20 → 480890
  将每条结果记录+31字节按OR合并
  与上述时间掩码相交，写另一组本地状态/时间字段
```

`4F9810` 的REA指令证明本地UI与消息路径使用同类组件查询：实体虚表+B8取得容器，再虚表+50按类别2查询组件。但具体业务类名仍不能仅由类别数字推定。

### 2.1 方向相关分类

`057930` 首先要求 `(status & C0)==C0`。若status含20，直接分类1；否则比较向量分量，调用仍未解析的数学入口 `6A89CD`，经过两个浮点常量、360及3的整数化计算，与输入方向参数作差并以120折算，最终得到局部值d：

```text
d <= 15         → 分类1
15 < d < 45     → 分类4
d >= 45         → 分类2
```

另一状态分支 `(status & 88)==0` 写分类0；不满足清零条件时可保持已有值。15和45边界分别为 `jg` 和 `cmovl`，不是凭经验选取。**这是局部d的分类规则**：数学入口、传入方向编码、完整坐标/朝向单位仍未知，不能直接标为“前后左右的角度阈值”，也不写官方伤害或防御方向加成百分比。

### 2.2 时间读取与状态切换

以n表示保护函数 `1244AE3` 返回的低32位，P/Pt为+1A00/+1A04，C/Ct为+1A08/+1A0C：

```text
mask = (P != 0 && u32(n-Pt) < 1382) ? P : 0
if C != 0 && u32(n-Ct) > 716:
    mask |= C
```

边界：716不加入当前分类、717加入；历史分类1381仍保留、1382不保留。两项同时存在时可按OR得到6等组合值。计时单位与回绕真实性未确认，以上只使用32位无符号差。

`01B610` 仅在当前分类变化时处理：若原当前分类非零且已持续>716，将它和当前n写到历史分类/时间；然后写入新分类及其时间。相同分类不会在这个函数里反复重置时间。它不等于“收到一次盾防就刷新反击窗口”。

### 2.3 收到攻击结果的相交

`480890` 以52字节步长OR合并结果记录+49字节。一个分支先右移4再与mask及1相交，写+1A10/时间+1A14；另一个分支与mask及6相交，写+1A18/时间+1A1C。它们还有本地对象/关联状态条件。本轮没有证明该字节各位就是反击技能资格，也未证明这组后续字段的实际用途。

**纠正后的结论**：反击类型表、方向时间状态、收到的攻击标记目前是三条相关候选链。没有完整连接之前不合并成“盾反公式”，不使用这里的计时数值来计算反击次数。

## 3. 伤害文字消费端：收到的整数进入格式化

`430D20` 从消息缓冲区读取一组攻击结果，每组最前的32位值由 `430E70..430E72` 复制进展开记录；结果状态分拆、可选附加数据另行读取。消息路径不是本轮抓包，仍是静态读取者证据。

`431140..431173` 把每组52字节复制到局部结构，建立指向该结构的指针，调用 `0B5630(type=3, attacker, target, args)`。

`0B5630` 的对应分支从args+10取得结构指针、从结构+0读取整数。正数分支按实体关系选择本地化文字，直接把该整数传给 `54F6F0`；另一个文字/数值通道将同一值传给 `06C750` 的十进制格式。例子：`B5DC5/B5DC9` 和 `B5FCA/B5FCD`。这里数字读取后没有先按PVP倍率乘算再写到格式化参数。

这解释了为什么客户端能显示战斗伤害，却未必保有决定该数值的完整权威公式。修改文字表、提示参数或显示数字不能证明实际扣血/服务器判定改变。此结论限定在已追通的S_ATTACK显示分支，不否定其他技能、治疗或持续伤害有自己的消息路径。

## 4. PVP与工具边界

REA `search_strings` 对PVP、反击及RandomMoveLoc字面量本轮返回空列表；原始PE与先前REA名称表读取证据已经确认若干UTF16字符串确实存在，因此空列表不是不存在的证明。对REA技能解析指令中235处 `lea rdx,a...`，辅助回读原始PE操作数及UTF16文字后，确认三个chain字段的准确名称，没有找到包含pvp的文字。这只覆盖这些具名LEA，不是完整语义解析器清单；动态拼名、其他解析器与间接字段消费仍未排除。

REA IDA适配器对两次 `read_bytes` 返回 `capability_unavailable/unsupported_provider`，原始错误保留。表值因此由原始PE辅助读取，代码分支和调用关系则由REA返回；没有把辅助读取冒称REA能力。IDA返回完整函数体范围的能力仍不可用，不能把返回指令数换算覆盖百分比。
