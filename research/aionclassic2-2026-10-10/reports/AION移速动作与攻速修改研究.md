# AION 移速 动作与攻击速度修改研究

移速、动画播放速度和攻击请求计时分别由不同字段控制。最有价值的研究入口是 CharacterObject 家族的速度设置函数 `460440`、动画比例函数 `4BC390` 和本地攻击请求函数 `06A0B0`；只改面板缓存、武器说明或技能冷却，不能据此判断角色真实移动或攻击是否加快。

以下针对 Game.dll SHA-256 `834300c2a85b6427de2d4a4be2931ff2ea59fd70f48f31754f5c2181753bd786`。函数地址是 RVA，运行时地址为对应 Game.dll 模块基址加 RVA；对象字段须加到已确认的运行时对象指针上。静态基址 `180000000`、属性编号和对象偏移不能互换。

## 先选对修改对象

| 研究目标 | 具体位置和类型 | 已确认用途 | 用于判断修改效果 |
| --- | --- | --- | --- |
| 客户端移动速度 | CharacterObject家族对象 `+6C8`，float32 | 被速度设置函数写入，移动动画和向量限制路径读取 | 同时观察位移、动画及关联派生值；不能只看面板 |
| 同一速度的派生表示 | 同对象 `+6CC` 为速度平方，`+6D0` 为倒数，都是float32 | 位置差异比较和方向插值使用不同派生表示 | 单独写 `+6C8` 会留下不一致的平方和倒数，可能出现不同消费者表现不一致 |
| 本地速度缓存 | `Game.dll+D71CA0`，float32 | 仅本地对象身份匹配时由设置函数更新 | 它是缓存；尚无证据表明只改它就改变世界位移 |
| 攻击动画比例 | 同家族对象 `+508/+50A`，uint16；`+4F4`，float32 | `cattack` 分支使用两项间隔之比，再乘全局动画比例 | 分别量动画周期、请求产生间隔和伤害发生间隔 |
| 本地攻击时间门槛 | 对象 `+1C88`，uint32；全局 `Game.dll+D71BE0`，uint16 | `06A0B0` 用它们与保护时钟返回值比较 | 它比动画倍率更接近请求调度；仍有其他条件和服务端接受环节 |
| 时间基准调整状态 | 同对象 `+1C94`，float32；`+1C98`，uint32 | `05D140` 补充额度并可能重写 `+1C88` | 改动后立即恢复或表现漂移时，应追这些写入者 |
| 物理层运动向量 | CryPhysics的CLivingEntity对象 `+178/+17C/+180`，三个float32 | 已选运动请求分支把三项输入写入此处 | 与Game组件速度标量分开识别；当前已验证局部原指令写入，尚未做完整物理积分或游戏修改 |
| 动作状态 | 同家族对象 `+AB0/+AB4`；技能动作另有 `+14A8/+14AC` | 在不同动作处理路径中控制分支 | 不能把这些偏移合并为一个统一动作编号，也不能先给未知枚举命名 |

Player、AIObject等类共享部分速度接口；实体对象、组件对象和物品记录也有同偏移字段。识别对象须核对构造、虚表或调用传入的 `this`，不能靠扫描出相同数字确认。

## 移速要追设置链和覆盖来源

`460440` 接受 float32 速度 `s`，在正常有限输入下维护以下关系：

```text
object+38  = s
object+6C8 = s
object+6CC = float32(s*s)
object+6D0 = float32(1/s)  // 接近零时走特殊分支，写1
```

它还更新动画和状态。本地玩家匹配时再写全局缓存 `D71CA0`。因此研究时先在这个设置入口观察原来输入、对象身份和调用来源，记录下一次谁重新设置速度，比直接冻结面板缓存更能解释修改为什么恢复。

历史消息路径是 `430410→4EB620→组件虚表+248→460440`。最新已核对的 Player 原始虚表同一槽仍指向 `460440`。另有 `4BF3C0` 根据关联对象派生速度，再调用相同设置接口；其分支中出现的12和30不是已经证明的全角色速度上限。

不同速度消费者的作用也不同：`4677C0` 使用 `s²` 比较位置差异；`4C30CA→0B4B80` 使用倒数形成方向样式向量插值；`4BBA10` 有 `min(s,L)/L` 的平面向量缩放。方向变化、位置差异容差与坐标积分应分开研究。后续已用归档的CryEntitySystem和CryPhysics补证选定实体/物理接口，见下文；完整物理积分和实时对象类型仍须继续查证。

这里的实体指针来自组件 `this+8`：`4BBA10` 在取虚槽 `+178` 前重新加载它，`4BE930` 的末端提交也使用关联实体。不能拿 Player 自身虚表同一槽的地址当成这些调用目标；偏移数字相同，接收对象仍不同。

验证一个速度改动时，记录静止、正常行走、停止、转向和收到状态更新前后的对象字段，并分别测量本地坐标变化与服务器后续确认的位置。如果面板改变而坐标变化不变，应继续追执行消费者；如果短时改变后恢复，应追覆盖入口。以上是待执行的验证方法，当前未产生运行时修改结果。

## 攻击动画与请求间隔分开量

`4BC390` 的 `cattack` 分支令 `B=u16(object+508)`、`C=u16(object+50A)`、`G=float32(object+4F4)`，正常非零输入时：

```text
R = float32(float32(B/C)*G)
```

任一间隔为零时，这一分支回退到1后再乘G。例如 `B=2000、C=1000、G=1` 得到动画倍率2。这个算例说明画面播放比例，不是已经验证的两倍有效攻击频率。

动画比例也不是完全脱离攻击请求的显示数字：已定位 `47C940→47CC70→06A0B0`，动画事件参数会除以比例R，再参与构造请求缓冲区 `+C` 的uint16参数。但是同一攻击函数另有时间门槛，而且内部缓冲区尚未建立当前线路抓包与服务器接受绑定。

所以应同时记录三个量：完整攻击动画持续时间、本地请求构造次数和服务器返回的实际伤害事件。只看到角色挥得更快、只看到内部缓冲区字段变小，均不足以判断有效攻击次数增加。

## 已追入归档的实体和物理模块

GitHub Release的[bin64程序包](https://github.com/liminilove7/rea/releases/download/aion-research-20261011/client__programs__aion-bin64.zip)已有本地还原副本，共52个bin64文件。它包含CryEntitySystem、CryPhysics和CryAnimation，能够继续静态追查跨模块执行；[下载说明](../DOWNLOADS.md)明确归档不包含完整21.3GB客户端目录。分析模块可用与客户端可以完整启动是两个不同状态。

CryEntitySystem样本SHA-256为 `d99a60818f27bbe7f50ebef6e4ba6026b25b6d062b60db3ad3ae0eace22f4b90`；CryPhysics样本为 `7afd2f7080d8180888d47a790acb1e5ae31533ee260c6563e18661057cf7c38f`。二者与归档清单匹配。下表RVA必须分别加到对应模块，不能加到Game基址。

| 环节 | 原始RTTI虚表绑定及实际函数 | 当前指令行为 |
| --- | --- | --- |
| Entity取得关联物理对象 | CryEntitySystem CEntity主虚表 `+178→17530` | 优先返回 `this+110` 的指针，空时返回 `this+108` |
| 物理状态读出候选 | CryPhysics CLivingEntity主虚表 `+18→6C9E0` | 处理类型2状态记录；其中有从物理对象三项字段取回向量的路径，以及其他状态修正 |
| 物理运动输入候选 | CryPhysics CLivingEntity主虚表 `+20→6D2A0` | 请求类型1、模式3的选定分支将输入 `+4/+8/+C` 写入对象 `+178/+17C/+180`，并设置 `+28C` |
| Entity三项表示提交 | CryEntitySystem CEntity主虚表 `+478→7250` | 向 `+518/+51C/+520` 或另一组字段写三项表示，并按状态触发更新；不能把这些偏移直接叫作玩家世界坐标 |

Game `4BBA10` 请求类型2的状态，读取返回记录 `+18/+1C` 两个分量，计算候选L；随后用组件速度s限制向量，构造类型1、模式3的运动输入，再调用物理接口 `+20`。与上述CLivingEntity槽体对应，能够静态连接速度消费者和物理向量写入。**实际对象采用CLivingEntity实现时才适用此成员布局**；基类CPhysicalEntity和CRigidEntity的虚槽目标不同，运行时类型尚未采样。

对这两个原始片段另做了三组离线CPU实验：固定输入平面向量为(6,8)、候选L为10，依次给速度6、9、12。Game生成的运动输入，手工转交到CLivingEntity模式3片段后，结果如下：

| 组件速度输入 | Game生成的运动向量 | CLivingEntity三个字段的结果 |
| --- | --- | --- |
| 6 | 约(3.6,4.8,0) | 同一三项浮点值 |
| 9 | 约(5.4,7.2,0) | 同一三项浮点值 |
| 12 | (6,8,0) | 同一三项浮点值 |

这验证了**改变速度标量能改变已选运动输入分支**，而这个固定候选向量达到L后不再放大；不能把10叫作游戏全局移速上限。候选L、对象和寄存器是构造输入；实验没有运行前面的状态查询、数学分派、虚调用选择、物理积分、网络同步或服务器校验，也不是一条已执行的跨DLL原生调用。

## 本地时间门槛及动作覆盖

`06A0B0` 在已读分支先调用 `05D140(object, XMM1=0)`，再读取保护入口 `1244AE3` 返回值的低32位 `n`：

```text
threshold = u32(object[+1C88] + u16(Game.dll+D71BE0))
n <= threshold 时拒绝这个分支
通过后继续检查和构造请求；成功路径更新 object[+1C88] = n
```

`05D140` 还维护 `+1C94/+1C98`：时间差大于5000时按整段补充额度，每段约0.2，最高0.5。在适用动作和调整条件下，它又会重写 `+1C88`。这解释了为什么单次改变某个时间值，不能等同于稳定控制调度周期。5000、1000与时间换算相容，但这里保护时钟的运行时来源和单位尚未采集，不能把额度0.5直接命名为半秒前摇。

动作 `+AB4` 的1031/1028/1027/1029分支读取动作记录 `+920/+924`，计算调整量。当前只是具体枚举值和数据来源，完整业务名称尚未恢复。技能施放的 `+14A8/+14AC` 属于另一条动作路径；应该从一次明确操作的写入者反推动作语义，避免直接按偏移猜“取消后摇”。

当前重新取得的 Player 更新 `061C20` 从 `+14A8` 分派：动作1调用 `042860`，动作2调用 `046ED0`，动作9和10在各自条件满足时也调用 `042860`。`042860` 内部读取 `+14AC`，通过目标/方向相关条件后在 `042FF1` 调用 `06A0B0`。因此普通攻击动作研究应沿 `061C20→042860→06A0B0` 观察；动作编号9/10的完整业务名称仍未确认，不能统一命名成普通攻击或技能。

## 原始指令离线修改实验

已在软件CPU中执行同哈希 Game.dll 的三个原始片段，使用明确构造的对象、寄存器和时钟值，没有启动游戏。以下结果说明局部代码怎样响应改动，不能当成服务器接受结果。

| 实验 | 实际片段结果 | 对修改研究的意义 |
| --- | --- | --- |
| 完整速度设置前缀，输入6 | `+6C8=6、+6CC=36、+6D0≈0.166667` | 确认三个速度表示同步形成 |
| 完整速度设置前缀，输入9 | `+6C8=9、+6CC=81、+6D0≈0.111111` | 速度提高时平方和倒数也改变；直接写单字段不具备这一效果 |
| 速度设置前缀，输入0 | 平方为0、倒数槽为1 | 近零特殊分支不是通常的除零倒数 |
| cattack间隔2000/1000，全局比例1 | 动画倍率2 | 得到播放倍率，尚未通过后面的攻击调度 |
| 相同间隔，全局比例2 | 动画倍率4 | 全局比例也参与结果，不能只改一对间隔来归因 |
| 时间基准1000、间隔200，时钟1200 | 本地比较拒绝 | 等于截止值仍不通过 |
| 相同基准和间隔，时钟1201 | 本地比较通过 | 明确的无符号“大于”边界；后续其他检查仍在 |

设置前缀停在实体回调之前；动画实验直接进入已经选择好的cattack片段；时间实验不调用保护时钟或额度调整函数。所有输入、原指令字节、执行步数和停点都保存在[实验结果](../evidence/continuous/20261013-movement-action-speed/offline-original-field-experiments.json)。另有单字段改动的数据对照和uint32回绕例子，分别标明来源，未混作运行时实测。

[实验脚本](../client/analysis-code/continuous/emulate-movement-attack-fields.py)可重跑，`--speed`可重复传入速度值，`--output`必须指定尚不存在的输出文件。复现使用本机独立 `AION_Offline` Python环境中的Unicorn与Capstone；输出不会修改原始样本或正在运行的游戏。

## 不应当当作最终攻速的值

`396E80` 返回查询记录 `+1BE` 的uint16武器基础间隔。`1D90C0` 将它除1000后格式化显示，`1DA810` 用它划分快慢档。改变这一显示链，尚不能证明攻击调度变化。

`3B2500` 写 SkillItem `+50/+54` 的共享冷却表示，并可能按武器间隔缩放冷却。这不是上述 CharacterObject `+1C88` 的攻击门槛。`attackDelay=29` 是属性编号，不是 `Player+29` 的攻速地址；`max_speed` 的一条已读路径属于boid群集配置，也不是玩家移速上限。
