01

四个角色，各做一件事

不需要把整套工程一次学完。先分清“谁提出问题”“谁执行操作”“谁负责证明”。

YOU / 目标

你：明确分析问题

例如：客户端收到的移速，最后写到哪里？哪些是收到值，哪些是本地计算出来的值？你决定目标版本与分析范围。

CODEX / 推理

Codex：组织调查

拆分问题、选择工具与参数、读取结果、检查反例，必要时写小脚本核对。它需要依据工具证据，不能靠猜测填地址。

REA / 工具入口

REA：调用与证据

校验输入、绑定样本身份、选择提供方，将 CLI/MCP 请求转换成分析操作，并保留来源、原始结果与限制。

IDA / 分析引擎

IDA：读取二进制

建立数据库，识别函数、反汇编、生成伪代码、查找引用。输出受保护代码、分析完整性和接口覆盖范围影响。

在这套工作流中，“分析引擎”是 REA 选中的提供方。IDA、Ghidra、Hopper 的可用能力不同；本机这份 Game.dll 实测使用 IDA。图中的“本地”指工具执行位置，并不表示 Codex 模型一定在本机运行。

一轮调查，是怎样发生的？

点击下面六个步骤，观察问题怎样变成操作、结果怎样变成可核对的结论。这是本轮会话记录的教学演示。

调查：收到的移速写到哪里？

离线样本 · 非实时会话

先把大问题变成可检查的小问题

先找消息处理函数，再追传参和写入点，最后查看读取者。每个工具调用都要解决其中一个具体问题。

此时只有调查方向，没有证据支持的最终偏移。

Codex 的调查问题
1. 哪个消息带有速度 float？
2. 这个 float 通过什么调用链传递？
3. 组件写入哪些字段？
4. 动画 / 移动代码如何读取这些字段？
1 / 6 · 每一步都保留结论范围

遇到不完整结果，Codex 应换成较小的检查操作继续调查：例如函数 dossier 失败时，分别读指令、伪代码和引用。解析失败需要保留失败原因，不能当成“没有相关代码”。

接线：CLI 与 MCP 两条入口

两条入口都进入 REA 的共享分析工作流。MCP 是模型与工具之间的调用协议，不是反编译器。Codex 支持本地 STDIO MCP 服务。官方说明 ↗

A · 本轮实际使用

Codex 通过命令行调用 REA

Codex→命令工具→REA CLI
REA 的 IDA 适配器→IDA MCP 代理→IDA RPC

Codex 发出命令，JSON 返回工具结果；原始输出保存到文件。本轮主要分析采用此路径。

Codex→REA MCP 服务

实战：AION 的移速是怎样传下来的？

这是已经通过 REA 读取并核对的当前客户端路径。图中全部地址为 RVA；它们描述代码和字段位置，不能直接当作正在运行的角色地址。

消息路由器0x426F70内部消息 37 → 处理函数
S_ACTION 处理0x430410读取 payload+7 的 float
组件速度分发0x4EB620查找组件 → 虚表 +248
速度设置函数0x460440写值 → 计算 → 更新动画
+38收到速度的镜像6
+6C8收到的速度 s6
+6CC本地派生：s²36
+6D0本地派生：倒数 / 近零回退0.166667
D71CA0本地玩家条件缓存（RVA）6

颜色同时用文字区分：收到值 / 本地派生 / 条件缓存。全局缓存只有对象身份匹配本地玩家时才更新；右边示例假设该条件成立。

0x180460489: movss dword ptr [rcx+38h], xmm6
0x18046048e: movss dword ptr [rcx+6C8h], xmm6
0x1804604b3: divss xmm0, xmm6
0x1804604b7: movss dword ptr [rcx+6D0h], xmm0
交互示例 · 根据已读指令计算

改变“收到的值”，观察派生字段

这里模拟的是 float32 计算。输入范围只是教学控件范围，不代表游戏允许的移速上限。

s = 6 → s² = 36 → 1/s ≈ 0.166667

常见有限非零输入走倒数分支。

s 接近零时，该设置函数保存的“倒数”回退到 1。仅从这个分支不能推断整个游戏的移动规则；NaN 等异常输入未在本练习模拟。

CODE ADDRESS / 模块里的代码
首选 VA = 0x180000000 + 0x460440
= 0x180460440

RVA 是相对模块的坐标。实际运行时模块加载基址可能变化；文件偏移又是另一种坐标，需按 PE 节映射换算。

OBJECT FIELD / 对象里的字段
字段地址 = 组件指针 + 0x6C8

必须先知道那个组件实例的指针。模块基址 + 6C8 不等于角色移速地址。代码地址、对象字段和文件偏移不能混用。

再追一步：动画读取者

两个间隔怎样变成动画倍率？

S_ACTION 的 action=35 分支把 payload+B/+D 两个 u16 写到组件 +508/+50A。REA 读取 0x4BC390 后确认：匹配 cattack 的分支把二者相除，再乘 +4F4 的动画比例。

真实消费端指令摘录
0x1804bc5b9: movzx eax, word ptr [rbx+508h]
0x1804bc5c9: movzx ecx, word ptr [rbx+50Ah]
0x1804bc5ed: divss xmm6, xmm0
0x1804bc733: mulss xmm6, dword ptr [rbx+4F4h]

“基础 / 当前攻击间隔”的命名来自参考源码与结构对照。当前二进制已证明的是同步字段与动画比值；服务器允许的攻击次数还要另追时间门槛。

动画比值实验室

B、C 均非零时：float32(B/C) 再乘 G；任一为零时，这个分支先回退到 1，再乘 G。

2000 / 1000 × 1 = 2 倍
参考 1 倍
1.00×
计算结果
2.00×

图条按 0–4 倍展示；数值超过 4 倍时仍完整显示，图条到达展示边界。

05

读懂证据，才知道结论有多远

工具结果提供观察，Codex 根据上下文作解释。报告必须把“代码里看到了什么”与“据此推断了什么”分开。

OBSERVED · 观察

指令读了 +6C8，写了 +6CC

已读指令在具体地址出现乘法、倒数和写入。样本哈希、地址、提供方、原始输出都可核对。

INFERRED · 推断

这两个字段是基础 / 当前间隔

两个 u16 的同步顺序、动画除法、参考服务端结构相符，支持该业务解释；跨版本名称和单位仍需要标出依据。

UNKNOWN · 未知

保护计时的来源与单位

REA 已追到混淆调用链，但没有确认最终系统计时 API。不能仅因它参与时间比较，就写成 GetTickCount。

为什么不是所有能力都能在本机直接使用？

REA 能力随提供方、目标格式、宿主平台和配置变化。本轮 IDA 支持函数代码、指令、引用和 dossier；不支持的 CFG、完整函数体范围、数据库修订信息等保留未知。Windows Ghidra P0 对 DLL 的目标角色有限制；本次不能把 Game.dll 改个文件名就当成可分析 EXE。

服务端 Java 参考源码的 import-reference-source 在当前 Windows 环境返回 unsupported_host。因此此前的 Java 源码阅读、Git blob 核对属于辅助证据，并没有冒称 REA 已成功导入 Java。该失败保存在 server-reference-import.json。
