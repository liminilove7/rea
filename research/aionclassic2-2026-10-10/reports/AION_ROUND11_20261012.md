# AION 第十一轮：条件关系容器与连锁 UI 绘制

2026-10-12，本机 REA 6.1.0 → IDA 9.5 headless 实际分析。沿第十轮登记入口继续，确认了关系容器的清理、查询、图构造、条目交换以及 `chain_skill_prob2` 的一个 UI 消费者。当前仍未闭合“盾防事件 → 反击资格激活 → 点击施放 → 消耗资格 → 服务端接受”的链路。

## 样本、证据与结果

分析对象为本地 `samples/Game.dll`，SHA-256 为 `834300c2a85b6427de2d4a4be2931ff2ea59fd70f48f31754f5c2181753bd786`。下文地址为首选映像基址 `0x180000000` 下的静态 VA，不是实际游戏进程地址。

四批共 **39 次 REA 分析请求，29 成功、10 失败**。14 项核对通过，见 [verification.json](../evidence/round11/verification.json)。每份成功响应均通过其具名输出合同及 Evidence schema 核对，绑定同一源文件哈希，并要求分析前后的就绪状态为真。四批 `close_binary` 均正常；成功 Evidence 中可定位的三个私有目录已移除。另一次底层诊断单独计算，没有计入成功分析请求。

没有执行、附加或修改游戏，没有保存原样本数据库。源文件哈希保持不变。HTML 和 Release 仍为第九轮归档，本机新增内容未发布。

## 1. 清除的是登记结构，尚未证明消耗反击次数

`0x18039D600` 的返回指令流显示：

- 将容器开头两个 DWORD 写为 `2` 和 `0xC`。
- 遍历 `+0x8/+0x10` 指针区间，释放 40 字节节点并将槽置空，再把 end 设回 begin。
- 遍历 `+0x20/+0x28` 指针区间，清理关系节点里的两个向量，释放 56 字节关系节点并置空。
- 重置其他向量的 end；从 `+0x68` 开始，按 `0x10` 步长清理四个树状容器。

引用中两条直接代码引用来自 `39D860` 重建函数和 `0331B0`。其他三条为无函数上下文的数据引用。这个证据支持“登记结构清理”，不能命名为“盾反使用次数扣减”或“反击窗口超时清除”。

证据：[清理指令](../evidence/round11/ida95-registry-instructions/registry-reset-instructions.normalized.json)、[清理原始引用](../evidence/round11/ida95-registry-instructions/registry-reset-xrefs.evidence.json)。

## 2. 关系查询没有给出战斗中的可用判定

| 静态入口 | 已确认的行为 | 解释边界 |
| --- | --- | --- |
| `39E700` | 按第二个参数查全局容器 `D4B008` 的 `+0x68` 树；节点、关系 `+0x20`、DWORD 向量均存在且非空才返回该关系指针，否则零 | 证明关系存在，未证明冷却结束或反击已触发 |
| `39E770` | 两个输入值相等时返回 1；否则查同类树并沿关系的 DWORD 向量递归查询 | 支持关系可达性查询；不能直接当施放资格检查 |
| `39D780` | 查两个登记节点，比较它们 `+0x18` 的有符号 DWORD，存在时返回前者大于后者 | 可用于排序，字段业务含义未知 |
| `39F880` | 对 DWORD 区间调用传入比较器，分割、递归和移动元素 | 支持登记项排序；不等于随机概率计算 |

`39E770` 已核对的调用点包括 `1C9A30`、`1CA2C0`、`2750D0`、`278C50`，这些函数取得两个值后询问关系；完整调用者还包含 `13DF40`、`1E3660`、`2C4D60` 和若干包装函数。本轮没有逐一审计它们的完整业务上下文。

证据：[非空关系查询](../evidence/round11/ida95-condition-consumers/condition-query-instructions.normalized.json)、[递归关系查询](../evidence/round11/ida95-condition-state/condition-pair-query-instructions.normalized.json)、[调用原始引用](../evidence/round11/ida95-condition-state/condition-pair-query-xrefs.evidence.json)、[比较器](../evidence/round11/ida95-registry-instructions/registry-order-comparator-instructions.normalized.json)。

注意：对全局变量的 `xrefs_to` 返回 `type=data`，但带有函数上下文的指令仍可实际读取该变量。这类引用与“函数地址的数据引用”含义不同，不能统一剔除。对函数入口统计直接调用时，仍要单独核对代码引用及 call 指令。

## 3. 登记数据进入连锁图，交换顺序后进入 chainskill 表示

`281830` 遍历全局容器，分配 `SkillVertex/ChainVertex` 节点，复制类型、键和 `+0x18` 值；随后把关系内的 DWORD 项和 QWORD 项分别解析为图节点并建立边。它闭合“登记关系 → 连锁图构造”，并未观察到战斗事件的激活窗口。

`283F40` 按类型和键取一条关系，将其 DWORD 项复制到调用对象 `+0x850` 的向量，排除一个匹配值，并在 `+0x870` 记录 `181244AE3` 的返回值。时间单位、期限和实际超时消费者仍未知。

`284120` 要求两个输入对象满足类型与关联键一致等条件，查找到关系后，遍历 DWORD 项并交换两个匹配值，再调用 `39ECF0`，最后置全局更新标志。这更接近条目顺序调整的路径；其具体 UI 手势尚未命名。

`39ECF0` 读取登记关系，构造标签为 `101` 的表示，通过名称 `"chainskill"` 查找另一套全局树，并调用 `507710/507470/507950` 比较及更新表示。`39E830` 重建末尾也读取同名表示，查记录 `+0x790`，重排关系内的 DWORD 项。

**推断**：这些路径存在连锁条目配置与顺序恢复的机制。落盘位置、持久化时机、上述辅助函数完整语义均未核实，不能据此宣称已找到正式配置文件或战斗触发次数存储。

证据：[图构造](../evidence/round11/ida95-condition-consumers/condition-ui-update-instructions.normalized.json)、[条目复制与时间值](../evidence/round11/ida95-condition-consumers/condition-ui-select-a-instructions.normalized.json)、[交换路径](../evidence/round11/ida95-condition-consumers/condition-ui-select-b-instructions.normalized.json)、[刷新表示](../evidence/round11/ida95-condition-state/condition-state-refresh-instructions.normalized.json)、[重建末尾整理](../evidence/round11/ida95-registry-instructions/registry-finalize-instructions.normalized.json)。

## 4. chain_skill_prob2 已找到 UI 执行消费者

第九轮确认技能记录字段 `chain_skill_prob1/2` 位于 `+0x7A4/+0x7A8`。本轮沿构造函数中的 RIP 相对 LEA，在原始 PE 中定位表入口 `0x1807F5F78`，前三个 QWORD 为 `27E7B0`、`27EA10`、`27F2E0`。原始字节读取单独记为辅助证据，不冒充 REA Evidence，也不由这三个槽推断完整虚表长度。

`27EA10` 的真实 REA 指令及函数 dossier 都确认了这段消费：

```text
27EABC  读取另一个返回对象的 DWORD +0x64；无对象时此前默认值为 1
27EAD2  调用 541050 取得技能记录
27EADC  ECX = DWORD [记录 +0x7A4]
27EAE2  ECX *= EDI
27EAE5  ECX += DWORD [记录 +0x7A8]
27EAEB  与 100 作有符号比较
27EAFA  指令中另有 40/70 比较；成功伪代码合并为与 100/0 的分支
27EBC2  以最终标志 × 0xDC 选择参数组
27EC2E  参数进入 61A020 绘制调用；后续有多次同类绘制调用
```

在取得记录的这个分支里，标志初始为 1；计算值大于等于 100 或等于 0 时改成 0。两个记录字段参与的是 32 位整数乘加，不是已证明的“抽一次随机数”；`+0x64` 对象值的业务名仍未知，不能自行叫技能等级。

因此已找到 **`chain_skill_prob2` 的一个执行消费者，属于连锁 UI 绘制参数选择**。这不证明它是当前服务器接受反击请求的概率，也不证明盾防后仅有 10% 的反击资格。当前技能154资源包含 `chain_skill_prob2=10`，但 `chain_skill_prob1` 元素缺失；尚未验证缺失字段的默认值，本轮没有擅自代入零。

`27E7B0` 的指令呈销毁/条件释放形式；`27F2E0` 处理输入对象类型及几何、绘制相关调用。这三份返回体均未闭合一个技能施放请求。不能把虚表中出现回调理解为已经找到点击施放。

证据：[原始 PE 表定位](../evidence/round11/ui-node-original-pe.json)、[绘制指令](../evidence/round11/ida95-condition-consumers/chain-node-slot1-instructions.normalized.json)、[成功函数 dossier](../evidence/round11/ida95-condition-state/chain-node-slot1-dossier.normalized.json)、[实际 Evidence](../evidence/round11/ida95-condition-state/chain-node-slot1-dossier.evidence.json)。

## 5. 本轮分析失败与就绪状态诊断

首批八个请求均返回 `unreadable_output`，没有有效 Evidence。一次生产 `IdaSessionClient` 诊断保存了底层调用，发现分析前 `server_health.auto_analysis_ready=true`，读取 `39E830` 反编译内容及相关数据后，分析后变成 `false`。REA 拒绝这一执行结果。随后采用先引用和指令、最后单独 dossier 的批次继续，最后一批七项全部成功。

这是本次诊断确认的状态变化，不是所有十个错误的统一原因。另外两个错误发生于 `27FDE0` 指令请求和 `39E700` 引用请求，均报告健康返回缺少必需字段；缺字段的具体原因未知，原文见核对 JSON 的 failures。底层诊断保存的反编译内容只作诊断参考，不计为成功 REA 分析。

限定 `--provider ida --client codex` 的 doctor 检查健康；它仅确认注册与私有目录权限，没有启动 IDA 验证本次数据库。全环境检查还报告未安装的可选引擎和其他客户端，不能拿它要求安装本次分析不需要的工具。

证据：[底层诊断](../evidence/round11/ida95-finalize-diagnostic/diagnostic-summary.json)、[底层原始调用](../evidence/round11/ida95-finalize-diagnostic/producer-observations.json)、[限定范围 doctor](../evidence/round11/doctor-ida-codex.json)。
