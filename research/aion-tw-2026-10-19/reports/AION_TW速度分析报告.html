为什么单一数值不足以描述攻速

请求节奏：有明确间隔，也有计时状态

I = read_u16(B + 0x142DB40)
L = read_u32(A + 0x1E90)
T = protected_clock_result

threshold = (L + I) mod 2^32
if unsigned(T) <= threshold:
    return 0
# 还需目标、状态等前置条件
# 后续请求路径会写回 A+0x1E90 = T

这是观察到的加法再比较，不能擅自改写成“无符号时间差”。I在面板按1000换算为秒；T的物理单位与最终来源仍未完成证明。

普通分支中，较小I会放宽这一客户端门槛；是否增加服务端认定的攻击次数，需要单独验证。

动画：两个间隔值形成倍率

# 当前已审的cattack前缀分支
ratio = 1.0
if U != 0 and V != 0:
    ratio = float32(U / V)
animation_factor = float32(
    ratio * read_f32(C + 0x51C))

U/V对应C+0x530与C+0x532。这个局部分支的倍率增大，不是服务器伤害频率提升的证明。其他动作分支另有技能、状态与倍率选择。

  1. 可以做有针对性的客户端实验设计。已知模块相对间隔地址、对象成员类型、写入器和消费者；不再靠搜索一个面板数字猜测全部含义。

  3. 移速实验应保持派生状态一致。现有写入器会维护S、S²、倒数及部分通知；单改一处镜像的效果尚未验证。
